# CS-WebUI 2.5.0-beta.4.9

## Security: the page server holds both loopback addresses

WebUI's page server listens on `127.0.0.1` only, but opens the page at
`http://localhost:<port>`. Browsers try `[::1]` first, so in earlier releases
another process on the same machine that listened on `[::1]` at that port could
serve or receive the window's page instead of the application. CS-WebUI now
chooses a port that is free on both loopback addresses and holds `[::1]` on it
for the window's lifetime, passing connections through to WebUI's server, so no
other process can listen there (#27, #30). Remote attackers were never able to
reach these ports.

- The page stays at `http://localhost:<port>`; applications need no change.
- If no port is free on both addresses after 16 attempts, `Show*` and
  `StartServer` throw a `WebUiException` (the `Try*` methods log and return
  `false`) instead of using an unguarded port.
- `Url` read before the window is shown now chooses and holds the port first,
  and returns `http://localhost:<port>` (or `null` if no server could start)
  instead of the network address of the first interface.
- `SetPort` on a window whose server is running throws
  `InvalidOperationException`, and `TrySetPort` returns `false`. Before, the
  port moved and briefly left the old one unguarded. `SetPort(0)` lets
  CS-WebUI choose the port.
- After a window is destroyed, `[::1]` is released only once WebUI has stopped
  listening on `127.0.0.1`.
- The pass-through accepts at most 256 connections at once and backs off when
  accepting fails.
- A window's port choice is serialized, so `Url`, `SetPort` and `Show*` on
  different threads cannot leave a served port unguarded.

`CsWebUi.Native` callers that use WebUI's `Show`, `ShowBrowser`,
`ShowWebView`, `StartServer`, `GetUrl`, `SetPort` or `GetFreePort` directly
remain exposed until WebUI itself listens on both addresses; the
`CsWebUi.Native` README lists them.

## Security: .NET 10.0.14

The build and the NativeAOT samples move to .NET SDK 10.0.403 / runtime
10.0.14, which fixes CVE-2026-111497 (GHSA-p3jp-9v83-76w9, an out-of-bounds
write in the .NET Brotli decoder) (#28). `global.json` requires SDK 10.0.403 or
later.

## Official WebUI nightly 24c7d196e

Official WebUI 2.5.0-beta.4 assets are refreshed to upstream commit
`24c7d196edc63f5b777d465063c3d26731f52dea` (#29). The C header and its 112
exports are unchanged. Upstream hardening in this range:

- `webui_bind` reuses free ids and returns 0 when none are left instead of
  writing past its tables (`WebUiWindow.Bind` already throws on 0).
- Browser command lines are built with bounds, Windows registry strings are
  always terminated, and shutdown no longer touches a freed window.
- After a failed or partial WebSocket write, WebUI closes that client instead
  of sending it more frames (webui-dev/webui#728).
- `webui_set_profile` with an empty name and path selects the browser's
  default profile, and WebUI's own Firefox profile folder is now named
  `WebUIFirefoxProfile`, so users of that profile start with a fresh one.

WebUI still binds `127.0.0.1` only; the loopback guard above is still needed.
