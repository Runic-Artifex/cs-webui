# CS-WebUI 2.5.0-beta.4.8

## Official WebUI nightly 2b35db13f

Official WebUI 2.5.0-beta.4 assets are refreshed to upstream commit
`2b35db13f864031543f61816c496b1035c026340` (nightly CI run 39813510797), which
contains the upstream fixes for two CS-WebUI reports:

- webui-dev/webui#723 (`9264f7ae9`, PR webui-dev/webui#725): a client that
  stops reading no longer blocks WebSocket writes to every other window and
  client. WebUI held one process-wide lock around each WebSocket frame, so a
  stalled client could hold up all others for up to 30 seconds per frame.
- webui-dev/webui#724 (`597243906`, PR webui-dev/webui#726): a navigation
  event counts its URL argument. `WebUiEvent.ArgumentCount` is now 1 for a
  navigation event, and `GetString()` returns the URL instead of throwing
  `ArgumentOutOfRangeException`.

Further upstream fixes since `efac0e24d`:

- `9125b207c`: the HTTP server sets `TCP_NODELAY`, so small WebSocket frames
  are not delayed by Nagle's algorithm.
- `2b35db13f`:
  - `*_client` functions ignore an out-of-range connection id, and
    `webui_close_client()` reads the client once because a new connection can
    reuse its slot.
  - `webui_open_url()` escapes `"`, `\`, `$` and backquotes before passing
    the URL to `open`/`xdg-open`. Browser launch commands quote the URL as
    one argument.
  - Timeouts on Windows use a monotonic clock and no longer overflow a
    32-bit `long`.
  - Fixed a double free and use-after-free when showing a folder or file,
    a double free when no index file is found, leaks when a test port is
    probed or a WebSocket thread cannot start, and an index path buffer too
    short for long index file names.
  - The file handler length is passed as an `int`, as the C header declares.
  - Native-only behaviour: `webui_get_float_at()` parses numbers longer than
    20 characters, `webui_get_bool_at()` reads an empty argument as false, and
    `webui_return_float()` no longer overflows its buffer for large values.
    The CS-WebUI argument getters and `WebUiResult` parse and format these
    values themselves, so only direct `CsWebUi.Native` callers see a change.

The C header and its 112 exports are unchanged since `efac0e24d`; only
`src/webui.c` changed. The public CS-WebUI API is unchanged.

A new native test sends a navigation over the WebSocket protocol and checks
that the event exposes its URL.
