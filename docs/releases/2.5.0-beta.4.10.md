## Guard the user's close

`WebUiWindow.SetCloseHandler(Func<bool>?)` lets an application keep an
embedded WebView window open when the user closes it, for example to ask
about unsaved work. Return `false` to keep the window open; to ask
asynchronously, return `false`, ask, then call `Close()`.

| Window | Can keep the window open |
| --- | --- |
| Windows, WebView2 | Yes |
| Linux, WebKitGTK | Yes |
| macOS, WebKit | No; WebUI learns of the close afterwards, and the handler is not called |
| Browser window | No; the handler is not called |

`WebUiWindow.IsCloseHandlerSupported` tells whether the system asks.
`Close()`, `Dispose()`, `WebUiApplication.Exit()` and `Clean()` are never
refused and do not call the handler, including the second `delete-event` GTK
sends when WebUI closes the window.

## Window placement

WebUI can set a window's size and position but not read them, and
`SetPosition` accepts only 0..3000 × 0..1800. New members read and set the
native window of an embedded WebView directly:

- `WebUiWindow.TryGetPlacement(out WebUiWindowPlacement)` returns the
  restored bounds (signed position, size) and the maximized state.
- `WebUiWindow.TrySetPlacement(WebUiWindowPlacement)` places, maximizes or
  restores the shown window, with any position.
- `WebUiWindow.NativeHandle` returns WebUI's `webui_get_hwnd`.

| Window | Read | Set |
| --- | --- | --- |
| Windows, WebView2 | Restored bounds, maximized | Bounds, maximized |
| Linux, WebKitGTK on X11 | Size, position, maximized | Size, position, maximized |
| Linux, WebKitGTK on Wayland | Size, maximized (`HasPosition` is `false`) | Size, maximized |
| macOS, WebKit; browser windows | No | No |

WebUI raises no change event; poll `TryGetPlacement` or read it when the
window closes. On Linux the calls run on GTK's main loop.

## Translatable texts

`WebUiTexts` gives CS-WebUI's own texts stable keys (`WebUiTexts.Keys`) with
English defaults; `WebUiWindow.SetTexts` sets a window's texts.

- `WebUiFileHandlerResult.NotFound` answers with a 404 page in those texts.
- A throwing or oversized file handler gets a 500 page in those texts
  (without texts, the plain-text 500 is unchanged).
- `WebUiTexts.BannerScript`, run by the page, shows WebUI's bridge banners
  in those texts. It recognizes the banners by their element id and English
  messages at the pinned WebUI, so a future WebUI may leave them English.
- WebUI's 403 "Access Denied" page and its own 404 page for a `NotHandled`
  path stay English; WebUI offers no way to change them.

Real-window tests (`CSWEBUI_WEBVIEW_TESTS=1`) cover the close veto,
placement and the banner script on WebKitGTK and WebView2; CI runs the
non-window tests on every platform.
